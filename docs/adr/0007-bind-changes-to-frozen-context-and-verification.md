# ADR 0007: Bind changes to frozen context and verification

- Status: Accepted

Each Task fixes its applicable normative revisions in a Task Context Snapshot, and each Logic Work Item must obtain a Context Receipt for its target before editing. The sidecar preserves the initial workspace and semantic-symbol baselines, then derives the result revision, patch digest, changed paths, changed behavior-bearing Code Symbols, Planned Symbol bindings, and applicable receipt itself; a worker may claim those values in a Change Bundle but cannot supply them as observed proof. Completion is accepted only when that sidecar-owned revision and context digest have passing Verification Runs and an Accuracy Manifest connecting the Task Contract to the resulting commit; conflicting, stale, inaccessible, unavailable, ambiguous, or out-of-scope evidence produces an inconclusive or rejected result rather than guessed compliance. A coding agent cannot approve a rule change or review finding needed to legitimize its own patch.
